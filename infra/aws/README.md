# AWS Production Infrastructure — Deployment Runbook (ATOM-INFRA-506)

AWS CDK (TypeScript) definition of the production stack for the Multi-Tenant
Scheduling Framework. **Code only** — deploying requires AWS credentials and a
human-approved `cdk diff`. Nothing here deploys automatically.

## Stacks

| Stack | Resource | Config |
|---|---|---|
| `scheduler-vpc` | VPC | 2 AZs, 1 NAT, public / private-egress / isolated tiers |
| `scheduler-secrets` | Secrets Manager | jwt-secret, db-password (generated); twilio/anthropic/slack (empty placeholders) |
| `scheduler-rds` | RDS PostgreSQL 15 | Multi-AZ, db.t3.medium, 7-day backups, encrypted, deletion-protected |
| `scheduler-elasticache` | ElastiCache Redis 7 | cache.t3.micro, encrypted in-transit + at-rest |
| `scheduler-msk` | Amazon MSK | 2 x kafka.t3.small, TLS, 72h retention |
| `scheduler-ecs` | ECS Fargate + ALB + ECR | API (2 tasks, 1vCPU/2GB, ALB), notification (2), audit (2), debezium (1) |

Dependency order (enforced in `bin/app.ts`):
`vpc, secrets -> rds, elasticache, msk -> ecs`.

## Prerequisites

- Node 22+, AWS CLI v2, credentials for the target account (`aws sts get-caller-identity`).
- CDK bootstrap once per account/region: `npx cdk bootstrap aws://<account>/<region>`.
- Container images built and pushed to the ECR repos the ECS stack creates
  (`scheduler-api`, `scheduler-notification`, `scheduler-audit`) — the CI
  pipeline (ATOM-INFRA-507) does this on deploy.

## 1. Install

```bash
cd infra/aws/cdk
npm install
npm run typecheck   # tsc --noEmit — must pass
```

## 2. Populate external secrets (once, before first deploy)

`jwt-secret` and `db-password` are generated by Secrets Manager. Provide the
external-provider secrets out-of-band — values never live in source:

```bash
aws secretsmanager put-secret-value --secret-id scheduler/prod/twilio-auth-token  --secret-string "$TWILIO_AUTH_TOKEN"
aws secretsmanager put-secret-value --secret-id scheduler/prod/anthropic-api-key  --secret-string "$ANTHROPIC_API_KEY"
aws secretsmanager put-secret-value --secret-id scheduler/prod/slack-webhook-url  --secret-string "$SLACK_WEBHOOK_URL"
```

> If deploying secrets before the SecretsStack exists, create them first with
> `aws secretsmanager create-secret --name <name> --secret-string ...`.

## 3. Review & deploy (human-gated)

```bash
npm run synth                 # cdk synth — must exit 0, no CFN validation errors
npx cdk diff                  # REVIEW every IAM / security-group change
npx cdk deploy --all --require-approval broadening   # prompts on any broadening
```

Attach HTTPS by passing an ACM certificate ARN (adds a 443 listener + HTTP->HTTPS redirect):

```bash
npx cdk deploy scheduler-ecs -c certificateArn=arn:aws:acm:us-east-1:<acct>:certificate/<id> \
  -c corsAllowedOrigins=https://app.scheduler.io
```

## 4. Post-deploy verification

| Check | Command |
|---|---|
| API health | `curl -f https://api.scheduler.io/actuator/health` -> `{"status":"UP"}` |
| ECS running = desired | `aws ecs list-services --cluster scheduler` then `describe-services` |
| RDS backups | `aws rds describe-db-instances --query "DBInstances[].BackupRetentionPeriod"` -> `7` |
| MSK lag = 0 | `kafka-consumer-groups.sh --bootstrap-server <tls-broker> --describe --all-groups` |
| No secret literals | `grep -rn "password\|secret\|token" lib/` -> only ARNs / Secrets refs, no values |

## Next.js frontend

Deployed separately to Vercel or AWS Amplify (CDN, auto-deploy from `main`),
pointed at the ALB / `api.scheduler.io`. Not provisioned by these CDK stacks.

## Security invariants (must hold)

- All credentials via `ecs.Secret.fromSecretsManager` (`valueFrom`) — zero
  environment literals for sensitive config, zero secrets in images or source.
- Data stores (RDS/Redis/MSK) live in isolated subnets; ingress is granted only
  to the ECS task security groups.
- `cdk deploy --require-approval broadening`; CI uses OIDC role assumption — no
  long-lived AWS access keys stored as GitHub secrets.
